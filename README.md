ポートフォリオ:恋愛シミュレーションゲーム（動的Webアプリケーション）

本プロジェクトは、職業訓練におけるJava学習の集大成として制作したノベルゲーム形式のWebアプリケーションです。

一般的なポートフォリオでよく見られる「掲示板」や「ToDoアプリ」のような単純なデータ登録・表示（CRUD）ではなく、実際のWebサービス開発で求められる**「ユーザーごとの複雑なステータス管理」と「条件分岐ロジック」**をJavaでどこまで表現できるかに挑戦しました。
また、単なるブラウザ上のゲームにとどまらず、Webアプリケーションの仕組み（DB連携やセッション管理）をどれだけゲーム体験とシームレスに統合できるかをテーマに開発しています。

---

ーーシステム設計とロジックーー

 1. 「Love」と「Like」の双軸による動的なシナリオ分岐
本アプリの最大の特徴は、単なる1つの好感度ポイントの蓄積ではなく、「Love（恋愛感情）」と「Like（人間的信頼）」という2つの独立した変数を管理している点です。

ゲームは全52ターンの構造で進行します。プレイヤーが選択肢を選ぶたびにこれらのパラメータが変動し、どちらかが特定の数値になった際この2つの数値の高さによって次のシナリオ（Phase1〜5）が動的に分岐します。
特にPhase3～5においては、共通シナリオである `CommonPhase` クラスをベースとし、パラメータに応じて `LovePhase` や `LikePhase`、さらには両方が一定値を超えた際の `TruePhase` などを継承・派生させることで、ランダムかつリアルなシナリオ展開を実現しました。

2. 破綻を防ぐMVCアーキテクチャの徹底
分岐が複雑になるほど、コードはスパゲティ化しやすく、可読性が著しく低下します。これを防ぐため、Javaの王道であるMVCモデルを厳格に適用しました。
リクエストはすべてController（Servlet）で受け止め、パラメータの計算やPhase移行の判定といった複雑な処理はすべて各Logic（BO）クラスへ委譲しています。各フェーズのシナリオ処理も別クラスへ切り出し、多様性を意識した拡張性の高い設計を行いました。

3. MySQLを用いた「状態の永続化」と「やり込み要素」
プレイヤーが途中でブラウザを閉じても再開できるよう、MySQLを利用してセーブデータ機能を構築しました。
データ管理の工夫: ログイン時にすべてをセッションに復元するのではなく、ゲーム画面へ移行するタイミングで都度 `save_data` テーブルから最新の状態を取得するアプローチをとり、状態管理の不整合を防いでいます。
ユーザー体験の向上:ユーザー登録時にIDとは別にHN（ハンドルネーム）を登録させ、ゲーム内でキャラクターに名前を呼ばせる仕組みを実装しました。
やり込み要素: どのルートをクリアしたかの実績をDBに保存し、到達したエンディングに応じてギャラリー画面（`Art.jsp`）や獲得したポイントによりヒロインのプロフィール（`Prof.jsp`）等のコンテンツが解放されるシステムを構築しています。

4. AIを「開発パートナー」とした自己学習
職業訓練では学習範囲外であったフロントエンド技術（CSS/スタイルシート、JavaScript等）の実装や、未経験からの複雑なロジック構築にあたり、Gemini等のAIを積極的に活用しました。
ただし、提案されたコードをそのままコピペするのではなく、エラーログの解読や、「このコードはどういう理屈で動いているのか」をAIに質問する「壁打ち相手」として利用しました。自分で描いた設計図を元にAIと議論を重ね、最終的には必ず自分の頭でロジックを理解し、自身の環境に合わせて実装・デバッグをやり抜くプロセスを徹底しています。

ーー今後の課題と実装予定ーー

現在、さらなる完成度の向上に向けて以下の課題に取り組んでいます。

1. フロントエンドのパフォーマンス最適化
   ヒロインの立ち絵イラストについて、Live2Dでのリッチな稼働を見据えて高解像度（大サイズ）で用意した結果、Webブラウザ上での描画に遅延が発生しているため一時的に失くしています。現在はWeb表示に最適なサイズへのリサイズおよび圧縮処理による改善を進めています。

2. 「周回プレイ」に対応したセーブ状態の拡張
   現在、クリア実績はDBに登録されるものの、進行状況のセーブデータが1周目の最終ポイントのままになってしまう課題があります。クリア後に状態をリセットし、2周目を適切に開始できるよう、セーブ＆ロード機能のロジック拡張を構築中です。

3. 入力バリデーションの強化
   ユーザー登録時、IDに全角（日本語）が登録できてしまう状態のため、正規表現を用いた半角英数字のみのバリデーションチェックを実装予定です。

4. Pythonを用いた自作ツールの開発
　現在、Toolページ（`Item.jsp`）の内容物がない状態です。Webアプリケーションを作る中、同時並行でPythonを用いたアプリケーション(配信用アプリケーションOBS等)で使える素材を、AIを活用しながら学習し開発中です。
